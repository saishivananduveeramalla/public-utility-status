> **Course:** Essentials of Web Programming (EWP) Lab  
> **Degree Program:** B.Tech Computer Science & Engineering / Information Technology  
> **Academic Session:** 2026  
> **Architecture:** Full-Stack Web Application (Angular + Express.js)  
> **Target Region (Demonstration):** Greater Hyderabad Municipal Area (GHMC)

---

## 1. Project Abstract

The **Public Utility Status** web application is an integrated, full-stack citizen awareness and municipal grievance portal. It enables residents to check the real-time operational availability of essential public services, report civic problems, track grievance resolution milestones, and read public maintenance advisories.

The application is built using a decoupled full-stack architecture:
- **Frontend:** Angular Single Page Application (SPA) written in TypeScript, styled with responsive HTML5 and CSS3.
- **Backend:** Node.js REST API powered by Express.js running on port 3000.
- **Data Exchange:** Fetch API utilizing JSON payloads.
- **Standalone JS Demo:** A dedicated client-side validation demonstration in `app.js` and `javascript-demo.html` that runs independently without Angular.

---

## 2. Project Objectives

- Provide a single, centralized portal for citizens to verify public utility availability across Greater Hyderabad.
- Implement an Express.js REST API with endpoints for utilities, announcements, and complaint registration.
- Provide client-side form validation (10-digit mobile, valid email, minimum length) on both Angular and standalone JavaScript.
- Issue unique grievance ticket identifiers (`CMP-HYD-2026-XXXX`) generated by the Express backend.
- Demonstrate asynchronous communication using the Fetch API (`GET` and `POST` methods).
- Provide a clean, beginner-friendly codebase suitable for first-year B.Tech lab evaluation.

## 3. Technologies Used

### Frontend
- **HTML5:** Semantic layout elements (`<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<footer>`, `<form>`, `<table>`).
- **CSS3:** Custom civic light theme (Blue, Green, White), CSS Grid, Flexbox, status badges, and responsive media queries.
- **JavaScript (ES6+):** Form validation logic, DOM manipulation, and standalone client-side execution in `app.js`.
- **TypeScript:** Type-safe models (`Utility`, `Complaint`, `Announcement`, `DashboardStats`), services, and strict compile-time checks.
- **Angular (v22):** Standalone components, reactive Signals (`signal`, `computed`), Reactive Forms, and client-side routing.

### Backend
- **Node.js:** Server runtime environment.
- **Express.js:** Web server framework providing REST API endpoints on port 3000.
- **CORS:** Cross-Origin Resource Sharing middleware enabling communication with the Angular frontend on port 4200.

### Data Exchange
- **JSON:** Data interchange format for utilities, complaints, and advisories.
- **Fetch API:** Native asynchronous HTTP requests (`GET`, `POST`) with `async`/`await`.

## 5. Backend REST API Endpoints

The Express backend listens on `http://localhost:3000`:

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/utilities` | Returns all 6 public utilities in JSON format. |
| `GET` | `/api/utilities/:id` | Returns details of a specific utility by its ID (e.g., `U101`). |
| `GET` | `/api/announcements` | Returns all public maintenance notices and advisories. |
| `GET` | `/api/complaints` | Returns all lodged complaints stored in memory. |
| `GET` | `/api/complaints/:id` | Returns complaint details matching the given complaint ID. |
| `POST` | `/api/complaints` | Validates input, generates a unique ID (`CMP-HYD-2026-XXXX`), stores in memory, and returns HTTP 201 Created. |

## 6. Installation & Execution Instructions

### Prerequisites
Make sure **Node.js** (v18.0.0 or higher) and **npm** are installed:
```bash
node -v
npm -v
```

### Option A: 1-Click Launch (Recommended for Windows)
In Windows File Explorer, navigate to:
```
C:\Users\Dell\.gemini\antigravity\scratch\public-utility-status
```
and double-click **`start-all.bat`**.  
This automatically opens both servers in separate command windows!

---

### Option B: Manual Execution via VS Code Terminals

#### 1. Start the Express Backend (Port 3000)
Open a terminal in VS Code and run:
```bash
cd backend
npm install
npm start
```
*Output should display:*
```
PUBLIC UTILITY STATUS - EXPRESS BACKEND API
Running at: http://localhost:3000
CORS enabled for Angular frontend (http://localhost:4200)
```

#### 2. Start the Angular Frontend (Port 4200)
Open a **second terminal** in VS Code and run:
```bash
cd frontend
npm install
npm start
```
*Output should display:*
```
Application bundle generation complete.
➜  Local:   http://localhost:4200/
```

#### 3. Open in Web Browser
- **Angular Full-Stack Web App:** [http://localhost:4200/](http://localhost:4200/)
- **Standalone JavaScript Demo:** [http://localhost:4200/javascript-demo.html](http://localhost:4200/javascript-demo.html)
- **Backend API Root:** [http://localhost:3000/](http://localhost:3000/)

## 7. Step-by-Step Testing Guide for External Examiner

### Test 1: Dashboard Overview (Page 1)
1. Open `http://localhost:4200/`.
2. Notice the green indicator: **"Express REST Backend Connected (http://localhost:3000)"**.
3. Inspect the 4 statistics cards at the top (**Total: 6**, **Operational: 3**, **Maintenance: 2**, **Disruptions: 1**). Explain to the examiner that these numbers are computed dynamically from data received from `GET http://localhost:3000/api/utilities`.
4. Click **"View Details"** on any utility card to display the modal popup.

### Test 2: Utility Status Directory (Page 2)
1. Click **"Utility Status"** (`/utilities`).
2. Type `"Secunderabad"` in the search input; observe real-time filtering to Water Supply.
3. Select **Category: Electricity** or **Status: Maintenance** to demonstrate multi-parameter filtering.
4. Toggle between **Card View** and **Structured Table View**.

### Test 3: Report a Problem & Fetch POST (Page 3)
1. Click **"Report Problem"** (`/register-complaint`).
2. Try submitting an empty form. Notice that submission is prevented.
3. Enter an 8-digit mobile number or invalid email. Notice real-time red validation error messages.
4. Fill in valid inputs:
   - **Name:** `A. Ramesh`
   - **Mobile:** `9848011223` (10 numeric digits)
   - **Email:** `ramesh@example.com`
   - **Category:** `Electricity`
   - **Area:** `Banjara Hills`
   - **Description:** `11kV feeder line tripped due to rain; low voltage in street 4.`
5. Click **"Submit Grievance"**.
6. The frontend sends a `fetch()` `POST` request to `http://localhost:3000/api/complaints`.
7. The Express backend validates the data, creates a unique ID (e.g. `CMP-HYD-2026-4819`), stores it in memory, and responds with HTTP 201 Created.
8. A green success confirmation card appears with the generated ID and a **Copy ID** button.

### Test 4: Track Grievance Status (Page 4)
1. Click **"Track Status"** (`/complaint-status`).
2. Enter the ticket ID generated in Test 3 (or click "Track This" on one of the sample rows).
3. The frontend sends a `GET` request to `http://localhost:3000/api/complaints/CMP-HYD-2026-XXXX`.
4. An interactive **3-Step Progress Timeline** visually highlights the current stage:
   - *Step 1: Grievance Submitted*
   - *Step 2: Field Squad Dispatched (In Progress)*
   - *Step 3: Rectified & Resolved*

### Test 5: Public Announcements (Page 5)
1. Click **"Announcements"** (`/announcements`).
2. Confirm that advisories are loaded from `GET http://localhost:3000/api/announcements`.
3. Click category filter pills to filter advisories by Electricity, Water, Roads, etc.

### Test 6: Standalone JavaScript Demonstration (`app.js`)
1. Click the **"JS Demo (app.js)"** pill in the navigation bar OR visit `http://localhost:4200/javascript-demo.html`.
2. Notice this is an independent HTML page connected directly to `app.js`.
3. Try entering an invalid phone number or invalid email. Notice the client-side JavaScript error messages displayed in the DOM.
4. Fill valid inputs and click **"Validate & Submit"**. A ticket card is generated dynamically in the DOM by `app.js`.

## 8. Troubleshooting Common Issues

| Issue | Cause | Solution |
| :--- | :--- | :--- |
| **"Backend Offline (Using local data)"** | Express backend not running on port 3000. | Open terminal, `cd backend`, and run `npm start`. Then click "Retry Connection" on the dashboard. |
| **`Port 3000 or 4200 already in use`** | A previous instance is running. | Close any existing Node command prompt windows and restart. |
| **`ng: command not found`** | Angular CLI not installed globally. | Always use `npm start` inside the `frontend` folder (uses locally installed CLI). |
| **Complaints disappear after backend restart** | In-memory server storage resets. | Expected design for this lab demonstration (no database required by syllabus). Complaints also back up to browser `localStorage`. |

---

## 9. Project Limitations

1. **In-Memory Storage:** The backend stores complaints in a JavaScript array in `data.js`. When the Express server is stopped and restarted, newly submitted complaints reset to initial sample records.
2. **Fictional Data:** All utility uptimes, areas, and notices are demonstration data for Greater Hyderabad.
3. **No Database:** As specified in the syllabus requirements, no relational or NoSQL database is utilized to keep the project simple for a first-year undergraduate examination.
